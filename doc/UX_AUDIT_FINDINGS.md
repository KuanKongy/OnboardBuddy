# OnboardBuddy — Usability, Utility & UI/UX Audit Findings

**Date:** 2026-07-22
**Build audited:** `main` @ `dda6d28` (running Docker stack: frontend `:5173`, backend-api `:3000`, worker)
**Method:** Five parallel read-only code audits (accessibility, data-lifecycle, user-flows, polish/correctness, backend-UX) cross-checked against a live browser walkthrough (signup → login → dashboard → onboarding reader → dependency graph → architecture → team → account settings, in both dark and light themes). Every item was verified against current source — findings the recent Phase 1–6 UI/UX pass already fixed are excluded.

**How to read:** Each finding is tagged **[HIGH] / [MED] / [LOW]** with a `file:line` anchor, then *what's wrong → why it hurts the user → suggested fix*. Severity reflects user impact, not effort.

---

## Top priorities (start here)

1. **Cross-tenant data leaks & writes** — three GET routes and one PATCH route fetch/modify by child-object ID without scoping to the project, letting any user read or alter *other teams'* code snippets, walkthroughs, and package status (§A1–A4).
2. **Unauthenticated signup endpoint pre-registers any email as confirmed** — enables invitation hijacking (§A5).
3. **Import preflight safety-gate is bypassable and its checkbox is frozen** — the cost/size acknowledgment can't be ticked yet analysis starts anyway (§C1).
4. **A failed package fetch masquerades as "no package — Generate"** — pushes users to start a *paid* regeneration of a package that already exists (§B1).
5. **API origin is hardcoded to `localhost:3000` and baked into the production bundle** — the frontend image only works when the browser is on the Docker host (§I1).
6. **Repo/branch pickers aren't paginated** — teams with >100 repos or >30 branches literally cannot select their target (§C2).

## A. Security & tenant isolation (backend)

- **[HIGH]** `backend/src/api/routes/onboarding.ts:606` — **`PATCH /sections/:sectionId/review` updates by section id alone (`WHERE id = $3`), with no `project_id` scoping.** Any user who is owner/admin of *any* project can approve/un-approve sections and flip package status in another team's project by guessing/enumerating a section UUID — a cross-tenant write. *Fix: join through `onboarding_packages` and require `op.project_id = req.params.id`, as the regenerate route already does (onboarding.ts:22-28).*
- **[HIGH]** `backend/src/api/routes/onboarding.ts:470` — **`GET /sections/:sectionId/receipts` returns `source_receipts` (code snippets, file paths, symbol summaries) with no project scoping.** Cross-tenant read of another team's private source. *Fix: join `package_sections → onboarding_packages` and filter `op.project_id = req.params.id`, else 404.*
- **[HIGH]** `backend/src/api/routes/workflows.ts:42` — **`GET /:workflowId/walkthrough` selects the workflow and steps by id only, not scoped to the project.** Leaks another project's file paths, symbol names, and step explanations. *Fix: join `analysis_snapshots` and require `s.project_id = req.params.id`, mirroring graph.ts:357-362.*
- **[HIGH]** `backend/src/api/routes/auth.ts:9` — **Unauthenticated `POST /auth/signup` creates accounts with `email_confirm: true` for any email, no ownership check, no rate limit.** The real app signs up via supabase-js, so this endpoint is an unused bypass: an attacker can pre-register a victim's email as a confirmed account and, since invitations match purely by email, accept invites addressed to that victim and read the team's docs. *Fix: remove the endpoint (or drop `email_confirm` and add rate limiting).*
- **[MED]** `backend/src/api/routes/members.ts:57` — **`permission_tier` on invitations is not validated; `"owner"` is accepted and inserted verbatim on accept.** An admin can mint a second, irremovable owner (bypassing the "use ownership transfer" and "cannot remove the owner" guards); a typo'd tier throws a 500 instead of a 400. *Fix: whitelist `["admin","developer"]` (and `developer_role`) with a 400 before insert.*
- **[MED]** `backend/src/api/routes/github.ts:160` — **OAuth/link catch-alls return `err.message` verbatim (400), and lib errors embed raw GitHub/Supabase response bodies.** Users see leaked internal payloads, and genuine server failures are mislabeled as client 400s. *Fix: whitelist known user-facing errors for 400; map the rest to a generic 500.*
- **[MED]** `backend/src/api/app.ts:10` — **No rate limiting anywhere; `POST /api/auth/login` proxies `signInWithPassword` with unlimited attempts.** Brute-forceable, and because all attempts share the backend's IP, Supabase's own throttling degrades auth for everyone. *Fix: `express-rate-limit` on `/api/auth/*` (e.g. 10/min/IP).*
- **[LOW]** `backend/src/api/routes/members.ts:83` — **Invitations are inserted with no `expires_at`, and the accept path treats NULL as never-expiring.** Pending invites grant access indefinitely. *Fix: set `expires_at = NOW() + interval '14 days'` on insert.*

## B. Onboarding & analysis data-state

- **[HIGH]** `frontend/src/lib/onboardingData.ts:41` — **`fetchOnboardingPackage` catches *all* errors and returns `null`, so the reader's `pkgFetchError` branch is dead code.** Any network/500 failure renders the "No package for {role} — Generate" empty state (OnboardingPage.tsx:1152), telling the user their existing package doesn't exist and inviting them to start a **paid** LLM generation. *Fix: rethrow (or return a discriminated error result) so `loadPkg`'s catch can show a real error + Retry.*
- **[MED]** `frontend/src/pages/OnboardingPage.tsx:1125` — **The reader has no loading state for the package fetch;** `pkg` starts `null` so `isMissing` immediately paints the false "no package / Generate" screen while the first fetch (and every role/package switch) is still in flight. *Fix: track `pkgLoading` and show a spinner until the first fetch settles.*
- **[MED]** `frontend/src/pages/OnboardingPage.tsx:639` — **`handleRegenerateSection`'s 4s poll interval is a local variable, cleared only from inside its own callback; the unmount cleanup misses it.** Navigating away mid-regeneration leaves an orphaned interval hitting the API every 4s and calling `setState` on an unmounted page for up to 2 minutes. *Fix: store it in a ref and clear it in the existing unmount cleanup.*
- **[MED]** `frontend/src/pages/ProjectOverviewPage.tsx:452` — **`packagesError`/`statusError` are only surfaced in the `neverAnalyzed` branch.** On an already-analyzed project, a failed packages/status fetch silently hides the Packages grid and Active-runs with no error and no retry, so a transient failure looks like "zero packages, nothing running." *Fix: render an inline error-with-retry whenever `packagesError || statusError`, regardless of `neverAnalyzed`.*

## C. Import & GitHub connection flow

- **[HIGH]** `frontend/src/pages/ImportPage.tsx:330` — **The import wizard renders `<PreflightPreviewCard>` without the `acknowledged`/`onAcknowledgedChange` props.** When the preview returns `confirmationsRequired`, the "Requires acknowledgment before starting" checkbox is a frozen controlled input that can never be ticked, and "Start analysis" is gated only on `startingAnalysis` — so the cost/size-cap safety gate is silently bypassed on the exact first-run flow where oversized-repo warnings matter most. `AnalyzeDialog.tsx:148` does this correctly. *Fix: wire a `confirmed` state into the card and disable Start while `confirmationsRequired.length > 0 && !confirmed`.*
- **[HIGH]** `frontend/src/pages/ImportPage.tsx:479` — **Repo/branch pickers are fed by unpaginated GitHub calls:** `listInstallationRepos` fetches one page of 100 (`github.ts:278`), `listBranches` uses GitHub's default 30 (`github.ts:300`). Users with the App on >100 repos, or a repo with >30 branches, cannot find their target — no error, no search, hard blocker for exactly the org-scale teams this targets. *Fix: paginate both to exhaustion via `Link` headers and add a type-to-filter search to the repo picker.*
- **[MED]** `frontend/src/pages/ImportPage.tsx:484` — **Already-imported repos aren't marked or filtered, and the resulting 409 "Project already exists" is a bare error with no link to the existing project.** Common after a mid-wizard refresh: user re-selects a repo, fills the form, clicks Import, dead-ends. *Fix: cross-reference `useProjects` to badge/disable imported repos, and link the 409 to the existing project id the backend already knows.*
- **[MED]** `frontend/src/pages/ImportPage.tsx:91` — **The two-step wizard keeps `createdProjectId` and step-1 selections only in component state.** Refreshing on "Step 2 of 2" silently returns to an empty step 1 even though the project was already created (then retrying step 1 hits the 409 above). *Fix: persist the created project id in the URL (`/import?project=<id>`) or sessionStorage and restore step 2.*
- **[MED]** `backend/src/worker/index.ts:780` — **The orphan reconciler only rescues `status='running'` jobs.** A job whose DB row committed but whose Redis enqueue failed stays `queued` forever (enqueue happens after COMMIT in projects.ts/onboarding.ts/webhook), pinning the project to `analyzing`, showing a "Waiting for worker" card that polls forever, and 409-ing every retry as "already being analyzed." *Fix: also fail `queued` jobs older than a few minutes with no matching Redis job (or mark the row failed when the post-commit enqueue throws).*
- **[LOW]** `backend/src/worker/index.ts:244` — **BullMQ `attempts: 2` is a no-op:** the first failure stamps the DB row `failed`, so the retry immediately hits the `KillSwitchError` guard and exits silently. Transient errors (GitHub 502, network blips) surface as hard "Failed" runs needing manual Resume. *Fix: only stamp `failed` when `attemptsMade + 1 >= attempts`.*
- **[LOW]** `backend/src/api/routes/projects.ts:159` — **When no branch is supplied and the GitHub repo fetch fails (revoked access / deleted repo), it becomes a generic 500.** *Fix: map GitHub 404/403 to a 422 "repository not accessible — check the installation."*

## D. Authentication & account flow

- **[MED]** `frontend/src/pages/ResetPasswordPage.tsx:26` — **The page never reads Supabase's `#error=access_denied&error_code=otp_expired` hash on an expired/invalid recovery link,** so `ready` stays false and the user sees an infinite "Waiting for your reset link… open it on this device" spinner — the *most common* failure of this flow shows actively misleading copy and never times out (unlike AuthCallbackPage's 10s guard). *Fix: parse hash/query error params on mount and show "This reset link has expired — request a new one."*
- **[MED]** `frontend/src/pages/LoginPage.tsx:44` — **"Sign in with GitHub" drops the deep link.** Email login preserves `location.state.from`, but `signInWithGithub()` redirects to `/auth/callback` with no `next`, so a logged-out user following a shared `/projects/x` link who signs in with GitHub (the primary path) lands on the dashboard. *Fix: pass `redirectTo=${origin}/auth/callback?next=${encodeURIComponent(from)}`.*
- **[MED]** `frontend/src/pages/LoginPage.tsx:76` — **None of the four auth pages set `autocomplete`** (login lacks `email`/`current-password`, signup lacks `email`/`new-password`, forgot lacks `email`, reset lacks `new-password`) — while AccountSettingsPage sets them correctly, proving the omission is accidental. Password managers won't reliably save/generate, and browsers may autofill the old password into "New password." *Fix: add the standard `autoComplete` values to each field.*
- **[LOW]** `frontend/src/pages/AccountSettingsPage.tsx:373` — **Unlinking a GitHub/email sign-in identity happens instantly on click with no confirmation,** while the *less* consequential GitHub-App disconnect on the same page gets a full confirm dialog. (Lockout itself *is* correctly prevented — `canUnlinkEmail` requires both identities — but removing a sign-in method is the more surprising action.) *Fix: reuse the disconnect-style confirmation for both unlink actions.*
- **[LOW]** `frontend/src/pages/AccountSettingsPage.tsx:538` — **The "Add email sign-in" dialog is a `<div>` with onClick buttons, not a `<form onSubmit>`,** so pressing Enter in the fields does nothing — inconsistent with login/signup/invite dialogs. *Fix: wrap in a `<form onSubmit>` with a `type="submit"` button.*
- **[LOW]** `frontend/src/pages/SignupPage.tsx:46` — **"Sign up with GitHub" has no loading state and doesn't mutually disable with the submit button** (LoginPage shares `loading || githubLoading`). Double-clicks can fire two OAuth starts. *Fix: mirror LoginPage's `githubLoading` + mutual disabling.*
- **[LOW]** `frontend/src/pages/ResetPasswordPage.tsx:110` — **Test convenience leaks into user copy:** the confirm field is labeled "Confirm new" (truncated) and the mismatch reads "The two entries don't match." *Fix: "Confirm new password" / "Passwords don't match," and use exact-match label queries in tests.*

## E. Invitations & team management

- **[MED]** `backend/src/api/routes/members.ts:83` + `frontend/src/pages/TeamPage.tsx:305` — **"Inviting" only inserts a DB row — no email is ever sent — yet the dialog collects an "Email address" and the button says "Send".** The invitee only ever discovers the invite if they independently sign up with that exact email and open /invitations. *Fix: either actually send the email, or relabel to "Create invitation" with a "No email is sent — share the link yourself" hint.*
- **[MED]** `frontend/src/pages/InvitationsPage.tsx:221` — **The Decline button is permanently disabled (no decline endpoint exists), and the list also shows expired invites** (the query filters only `status='pending'`, ignoring `expires_at`) that the accept endpoint then rejects with "Invitation not found or expired." Unwanted invites clutter the page forever; expired ones look acceptable but error on click. *Fix: add a decline endpoint + enabled button, and filter `expires_at > NOW()` (or show an "Expired" state).*
- **[MED]** `frontend/src/pages/TeamPage.tsx:208` — **There is no "Leave project" anywhere in the UI, and the backend forbids self-removal** (members.ts:216). Anyone who accepts an invite is a member forever unless an owner/admin removes them — a one-way door. *(Confirmed live: as a Developer, the Team tab shows members but offers no leave/exit control.)* *Fix: add a "Leave project" action + endpoint allowing self-removal for non-owners.*
- **[MED]** `frontend/src/components/ProjectCard.tsx:119` — **The card's "Delete project" menu shows for owner *and* admin, but the API requires owner** (projects.ts:486), so admins confirm then get "Insufficient permissions"; and for owners the card dialog needs no type-to-confirm, bypassing the type-the-repo-name protection ProjectSettingsPage enforces for the identical action. *Fix: gate the menu item to `owner` and reuse the type-to-confirm dialog in both places.*
- **[LOW]** `backend/src/api/routes/members.ts:67` — **Invite creation does no email trim/format check and doesn't reject self-invites or existing members.** A whitespace-padded/typo'd email creates an unacceptable invite; inviting an existing member dead-ends in a 409 on accept. *Fix: trim + regex-validate and reject self/existing-member with a 400.*
- **[LOW]** `frontend/src/pages/OnboardingPage.tsx:989` — **"Mark reviewed" renders only for owner/admin (API agrees), yet the tour sells it as "your progress tracker" and TeamPage shows "N sections reviewed" per member.** The actual onboardees (developer tier) can never track progress, so their metric is permanently 0. *Fix: either let any member toggle review, or reframe the copy/metric as admin content-approval.*

## F. Graph, architecture & workflow views

- **[MED]** `backend/src/api/routes/graph.ts:73` — **In the default directory-grouped dependency view, every group is built with `dependentCount: 0` hardcoded** while `importCount` is summed correctly. *(Confirmed live: `backend/src/` showed "403 imports · 0 imported by" despite two inbound edges drawn to it; drilling in, the inner file nodes show correct "imported by" counts.)* Every module reads as "imported by 0," falsely implying nothing depends on anything — the opposite of the tool's core value. *Fix: aggregate inbound cross-directory edges into each group's `dependentCount`.*
- **[MED]** `frontend/src/pages/GraphPage.tsx` (dependency search) — **Searching filters the match count but never recenters the viewport onto the matches.** *(Confirmed live: typing "workflow" showed "2 / 60 files" in the header while the canvas went completely blank — the two matches were laid out off-screen and the view didn't fit to them.)* Users see an empty canvas and assume search is broken. *Fix: fit the viewport to the filtered node set after a search resolves.*
- **[MED]** `frontend/src/pages/GraphPage.tsx:82` — **The `?focus=` deep-link param is re-resolved on every `loadGraph` and never removed from the URL.** On a clustered repo, clicking the "Dependencies" root breadcrumb or "Up one level" bounces the user straight back into the focused file's cluster (root unreachable), and drilling elsewhere shows a spurious "Could not find `<file>`" warning. *Fix: strip `focus` from the URL (via `setSearchParams` replace) once resolved, or ignore it for user-initiated navigations.*
- **[MED]** `frontend/src/pages/WorkflowsPage.tsx:137` — **The workflow-graph fetch (and the package-keyed loads in ArchitecturePage/CapabilitiesPage/ClassGraphSection/GraphPage) has no AbortController or staleness guard**, so the last response to *arrive* wins. Rapidly clicking through the workflow rail can leave workflow A's graph rendered while B is highlighted as selected. *Fix: abort or ignore responses that no longer match the current selection.*
- **[LOW]** `frontend/src/pages/GraphPage.tsx:208` (+ `ClassGraphSection.tsx:67`) — **The graph search input isn't debounced; each keystroke re-runs a full union-find + dagre (Sugiyama) re-layout** plus a complete React Flow re-render. On drilled-in clusters or non-clustered repos with hundreds of nodes, typing causes visible jank and nodes jumping mid-keystroke. *Fix: debounce ~150–250ms before the value feeds the layout memo.*
- **[LOW]** `frontend/src/components/graph/GraphFirstVisitHint.tsx:37` — **The first-visit hint copy is hardcoded to the files view ("map of how files depend… open it on GitHub") but the same component renders on the "Classes & interfaces" canvas,** where nodes are classes and there is no GitHub link. First-timers get instructions for a different view. *Fix: accept a variant/copy prop per view.*
- **[LOW]** `frontend/src/components/graph/ModuleNode.tsx:3` — **Leftover commented-out code shipped in a per-node component:** a commented import, a dead `const complexity`, and a commented JSX block with mismatched `<span>` tags (would not compile if uncommented). *Fix: delete them.*
- **[LOW]** Architecture view (AI-generated component summaries) — *(Observed live)* a component card read **"Database Schema: 0 files."** in its description while showing **"40 files"** in its footer count. Minor, but the contradictory numbers undermine trust in the generated summary. *Fix: reconcile the description's file count with the actual member count (or omit the count from the generated prose).*

## G. Accessibility & keyboard

- **[HIGH]** `frontend/src/App.tsx:107` — **No per-route `document.title` (every page keeps the static "OnboardBuddy") and no focus reset or live-region announcement on route change.** Tab/history entries are indistinguishable and screen-reader users get zero feedback that navigation happened. *Fix: a route effect that sets `document.title` per page and moves focus to the page `h1`/main on navigation.*
- **[HIGH]** `frontend/src/components/PackageSelector.tsx:132` — **The "make default" star is a nested `<button>` inside a Radix `DropdownMenuItem`, reachable only by pointer.** Radix roves focus across `menuitem`s and closes on Tab, so keyboard users can never set a default package. *Fix: make it its own menu item, or add a documented key handler on the item.*
- **[MED]** `frontend/src/App.tsx:93` — **No skip-to-content link and `<main>` regions aren't focus targets.** Keyboard users Tab through the logo, 4–9 nav links, tour/shortcut buttons, account card and theme toggle on *every* page before reaching content. *Fix: a visually-hidden-until-focused "Skip to content" anchor targeting `main` (`tabIndex={-1}`).*
- **[MED]** `frontend/src/pages/ImportPage.tsx:407` (+ TeamPage, ProjectSettingsPage, ArchitecturePage, ProjectOverviewPage) — **Many `<Label>`s lack `htmlFor` and their controls lack `id`/`aria-label`;** several fields (LLM-key input, delete-confirm input, graph search, the three overview filter selects) have no label at all. Screen readers announce them by placeholder/value only, and clicking the visible label doesn't focus the control. `AnalyzeConfigForm.tsx:144` shows the correct pattern already exists. *Fix: give each control an `id` + `htmlFor` (or `aria-label`).*
- **[MED]** `frontend/src/pages/ProjectSettingsPage.tsx:266` (+ Dashboard, Import, Team, Invitations, Onboarding, AnalyzeDialog, AccountSettings) — **Async error/status banners render without `role="alert"`/`aria-live`,** so a screen-reader user who saves/analyzes/invites never hears the failure or the "generating…" progress. LoginPage/SignupPage do it correctly. *Fix: `role="alert"` on error banners, `role="status"`/`aria-live="polite"` on async status.*
- **[MED]** `frontend/src/pages/DashboardPage.tsx:250` (+ ~13 other pages) — **Full-page loading is a bare spinning `Loader2` with no `role="status"`/sr-only text**, so during load a screen-reader user perceives an empty page. *Fix: wrap spinners in `role="status"` with an sr-only "Loading…".*
- **[MED]** `frontend/src/pages/WorkflowsPage.tsx:186` — **No `prefers-reduced-motion` handling anywhere** while the app runs continuous motion: every workflow edge is `animated: true` (perpetual marching dashes), plus `animate-pulse` dots, 500ms camera glides, and smooth scroll. Can cause dizziness/nausea for vestibular users who set OS reduced-motion. *Fix: a `@media (prefers-reduced-motion: reduce)` base rule and gate animation/glides behind `matchMedia`.*
- **[MED]** `frontend/src/pages/WalkthroughTab.tsx:310` (+ OnboardingPage, InvitationsPage) — **Selected item in several toggle lists is conveyed only by background color** (no `aria-pressed`/`aria-current`), while sibling code does set it. Screen-reader users can't tell which tutorial/section/role is active. *Fix: add `aria-pressed`/`aria-current`, matching the existing pattern.*
- **[MED]** `frontend/src/components/AnalysisRunPanel.tsx:177` + `PackageSelector.tsx:120` — **Pipeline phase status and package status are conveyed solely by icon color/shape** (and hover-only `title` on non-focusable spans). Status is color-only for sighted users and absent for keyboard/SR users. *Fix: add sr-only status words and `tabIndex={0}` on tooltip-trigger spans.*
- **[LOW]** `frontend/src/pages/TeamPage.tsx:340` — **Avatar initials are white text on `bg-amber-500`/`emerald-500`/`cyan-500`** (~1.6:1 on amber) — illegible for low-vision users. *(Live: the light-hue avatars on the Team page are borderline.)* *Fix: use `-600/-700` shades or dark text.*
- **[LOW]** `frontend/src/pages/OnboardingPage.tsx:1110` (+ several) — **Meaningful sub-12px text at reduced opacity** (`text-muted-foreground/50`, `opacity-50` at 10–11px) lands below the 4.5:1 AA minimum. *Fix: full-opacity muted token for small meaningful text.*
- **[LOW]** `frontend/src/pages/ProjectSettingsPage.tsx:278` (+ ProjectOverviewPage, OnboardingPage) — **Heading levels skip `h1 → h3` with no `h2`,** breaking the screen-reader outline. *Fix: promote card/block titles to the next sequential level.*
- **[LOW]** `frontend/src/components/AppTour.tsx:119` — **On tour end, focus isn't restored to the triggering element** (it grabbed focus into the card on open), dropping keyboard focus on `<body>`. *Fix: record `document.activeElement` on mount and restore it (SidebarShell already does this).*
- **[LOW]** `frontend/src/hooks/useHotkeys.ts:33` — **Global single-character shortcuts (`[`, `]`, `1`-`9`, `?`) are always active with no way to disable/remap** — a WCAG 2.1.4 issue for speech-input and tremor-prone users. *Fix: a persisted "disable keyboard shortcuts" preference.*
- **[LOW]** `frontend/src/components/SidebarShell.tsx:60` — **The sidebar toggle has `aria-label` but no `aria-expanded`/`aria-controls`.** *Fix: add `aria-expanded`.*

## H. Error handling & data lifecycle

- **[MED]** `frontend/src/pages/ProjectSettingsPage.tsx:251` — **A failed project deletion writes to the page-level error banner, but the confirmation dialog has no error slot and stays open,** so the message renders *behind* the modal — the delete looks like it did nothing. *Fix: render the error inside the delete DialogContent (TeamPage's remove-member dialog does this).*
- **[MED]** `frontend/src/pages/WalkthroughTab.tsx:262` — **`openTutorial`'s catch is empty; a tutorial that 500s shows a spinner then silently snaps back to the picker** — the click appears broken. Same shape at `openWorkflow` (line 277), which sets steps to `[]` and shows "No steps found," presenting a server error as authoritative "no data." *Fix: set an error state and show error-with-retry in the viewer pane.*
- **[MED]** `frontend/src/lib/api.ts:48` — **On a final 401 there's no shared redirect-to-login;** pages print raw text like "API error 401" until Supabase's SIGNED_OUT event eventually flips the route, and a transient-network refresh failure never signs out. *Fix: on final 401 in `apiFetch`, trigger a shared session-expired handler (sign out + redirect to /login with return path).*
- **[LOW]** `frontend/src/pages/DashboardPage.tsx:162` — **The activity-feed fetch swallows errors (`.catch(() => {})`)**, so on failure users with real activity see "No activity yet." *Fix: track an error flag and show a "couldn't load activity" note (the page's own `inviteCountError` pattern).*
- **[LOW]** `frontend/src/pages/ProjectOverviewPage.tsx:716` — **On run-history fetch failure, `runs` stays `null`,** so the error text renders together with a spinner that never resolves, and there's no retry. *Fix: set `runs = []` on error and add a retry.*
- **[LOW]** `frontend/src/pages/ProjectSettingsPage.tsx:135` — **The llm-key and ranking-weights loads swallow errors,** leaving a permanently empty role dropdown / "no key configured" with no hint anything failed. *Fix: error flag + inline retry in those cards.*
- **[LOW]** `frontend/src/components/PackageSelector.tsx:108` — **The "make default" star calls `void setDefaultPackage(...)` and never catches the rejection** — it can fail silently (no change, no message, unhandled promise rejection). *Fix: catch and surface a brief error / revert.*
- **[LOW]** `backend/src/api/middleware/project-access.ts:15` — **A non-UUID `:id` (truncated shared link) makes Postgres throw, caught as a 500** instead of a comprehensible 404 (same for `:invitationId`, `:jobId`). *Fix: validate UUID-shaped params up front (or catch pg `22P02`) and 404.*
- **[LOW]** `backend/src/api/app.ts:30` — **The global error handler ignores `err.status`,** so malformed-JSON (400) and payload-too-large (413) both surface as 500. *Fix: respect `err.status`/`statusCode` before defaulting to 500.*

## I. Deployment, performance & polish

- **[HIGH]** `frontend/.env:1` (+ `frontend/Dockerfile`, `frontend/src/lib/api.ts:3`) — **The API origin is hardcoded to `VITE_API_URL=http://localhost:3000/api` and baked into the built bundle** (verified: `localhost:3000` is literally present in `dist/assets/index-*.js`; the Dockerfile has no `ARG VITE_API_URL`, compose passes no build args, nginx has no `/api` proxy, and `frontend/.env` isn't committed so a fresh clone bakes `undefined/...`). Every API call from any non-localhost deployment fails. *Fix: add `ARG VITE_API_URL` wired from compose, or switch to a relative `/api` base + an nginx `location /api { proxy_pass http://backend-api:3000; }`.*
- **[MED]** `backend/src/api/app.ts:7` — **No `compression()` middleware, and large graph payloads have no node caps:** `/graph/classes` and `/graph/architecture` (incl. all cluster members) are uncapped, and `/onboarding/packages` runs 6 correlated subqueries per row with no LIMIT. On a large repo, multi-MB uncompressed JSON ships on every poll/navigation. *Fix: add `compression()` and cap/paginate those payloads.*
- **[MED]** `frontend/nginx.conf:1` — **The prod nginx config has SPA fallback only — no `gzip`, no `Cache-Control` for `index.html` or hashed `/assets/*`.** Big JS ships uncompressed every visit, and a heuristically-cached stale `index.html` can reference deleted chunks after a redeploy (broken app until hard refresh). *Fix: enable gzip; `no-cache` on index.html; `immutable, max-age=31536000` on `/assets/`.*
- **[LOW]** `frontend/index.html:3` — **No `<meta name="description">` or `theme-color`, and the theme-bootstrap `catch` forces dark mode when localStorage throws,** ignoring an OS light preference. *Fix: add the metas; fall back to `matchMedia("(prefers-color-scheme: dark)")` in the catch.*
